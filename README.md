# United Front — merged site

The planner (`/gvgplaner`) and the statistics dashboard (`/holyship`) are now one
page with five tabs: **Planner · Dashboard · Overall · Players · History**.

Nothing was rewritten for its own sake. The statistics half is the original code
with a wider router; the planner is the original code moved into a module and a
scoped stylesheet.

---

## What goes where

```
index.html                  one page, five tabs, one masthead
css/
  styles.css                statistics — unchanged
  planner.css               planner — every rule scoped to #view-planner
js/
  config.js                 all settings, both halves            ← edit this
  data.js                   spreadsheet reading — unchanged
  charts.js                 inline SVG charts — unchanged
  planner.js                the board, as window.UFPlanner
  app.js                    router + views (routing extended)
scripts/
  build-manifest.mjs        unchanged — keep your GitHub Action pointed at it
data/
  master.xlsx               ← copy from the holyship repo
  weeks/W01.xlsx …          ← copy from the holyship repo
  weeks/manifest.json       generated by the action
assets/
  united-front-planner.png  ← copy from the gvgplaner repo
Member.xlsx                 ← copy from the gvgplaner repo (sits next to index.html)
```

Four files to copy in before this deploys: `Member.xlsx`, the map PNG, and the
`data/` folder from the statistics repo. Everything else is here.

Also bring across your `.github/workflows/*.yml` that runs `build-manifest.mjs` —
it isn't in this bundle and its paths haven't changed.

## How the two halves stay out of each other's way

Both codebases used the class names `.roster`, `.toggle` and `.brand`, and both
defined `--panel`, `--radius`, `--font-display` and `--font-body` on `:root`.
Left alone, whichever stylesheet loaded second would have quietly restyled the
other one.

- Every planner rule is scoped to `#view-planner`. The planner's roster panel is
  now `.uf-roster`, so the statistics roster list keeps `.roster` to itself.
- `planner.css` declares no `:root` block. Its own tokens live on `#view-planner`
  and are prefixed `--uf-`; everything else reuses the statistics palette, so the
  board reads as part of the same site rather than a second theme bolted on.
- The four things the planner appends to `<body>` — drag ghost, confirm dialog,
  toast, and the `.btn` classes the dialog reuses — stay unscoped, because they
  are not inside the view. None of those names exist in `styles.css`.
- Element IDs did not overlap, so they were left as they were.

## Behaviour worth knowing

**The planner loads lazily.** `Member.xlsx` and the map PNG are only fetched the
first time someone opens the Planner tab. Landing on Dashboard costs nothing
extra. Opening the Planner tab is instant on later visits — the board is built
once and re-measured, not rebuilt.

**The two halves fail independently.** If `data/` is missing or broken, the
statistics tabs show the existing error panel and the Planner tab still works.
If `Member.xlsx` or the map image is missing, the planner shows its own error and
the statistics are unaffected. This is tested; it was the main risk in merging
two apps that each assumed they owned the page.

**Assignments survive the merge.** The `localStorage` key is unchanged
(`etheria-uf-planner/v3`), so anyone with a board saved on the old planner URL
keeps it — provided the site is served from the same origin. Moving to a
different path on the same domain keeps it; a different domain does not.

**Visitor counter.** Kept, moved into the shared footer, and it now counts the
whole site once rather than per tab (the URL hash is ignored).

## Things you'll probably want to change

All in `js/config.js`:

| Setting | Does what |
|---|---|
| `defaultView` | Which tab opens with no `#hash`. Currently `'planner'` — set to `'dashboard'` to land on the statistics instead. |
| `planner.boxes` | The 30 node positions, in % of the map image. Tick **Outline nodes** on the Planner tab while you tune them. |
| `planner.mapImages` | Paths tried in order for the map. |
| `planner.rosterFiles` | Filenames tried in order for the roster. |
| `houses`, `rankOrder` | Unchanged from the statistics app. |

## Running it locally

Both halves fetch spreadsheets, and browsers block `fetch` over `file://`, so
opening `index.html` by double-clicking will not work. Serve the folder:

```
python3 -m http.server 8000
```

then open `http://localhost:8000`. Image export also needs this — a canvas drawn
from a `file://` image is tainted and cannot be saved.
